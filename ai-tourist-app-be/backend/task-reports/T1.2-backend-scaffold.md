## What was implemented

### CORS middleware — `src/shared/middleware/cors.ts`
- Factory `buildCorsMiddleware()` reads `CORS_ALLOWED_ORIGINS` (CSV) from
  `config.cors.allowedOrigins`.
- Empty list + non-production → permissive (echoes any Origin, no credentials).
- Empty list + production → deny by default (no ACAO header).
- Non-empty list → echoes the request Origin if matched, otherwise no header.
- Wildcard subdomain matching: `*.example.com` matches `https://*.example.com`.
- Preflight OPTIONS includes the configured methods (`GET/POST/PUT/PATCH/DELETE`).
- Helper `buildCorsMiddlewareFor(allowed)` accepts an explicit list, used by
  tests to avoid coupling to the singleton config object.

### pgAdmin — `docker-compose.yml`
- Added `pgadmin` service on port 5050, `dpage/pgadmin4:8`, depends on
  Postgres healthcheck, persistent volume `aitg_pgadmin_data`.

### Migration `003_push_subscription`
- Drops `fcm_token` / `apns_token` columns from `users`.
- Adds a single `push_subscription TEXT` column (matches design.md §4).
- Idempotent (`ADD/DROP COLUMN IF [NOT] EXISTS`), so re-running is safe.

### App wiring
- `src/app.ts` now mounts `buildCorsMiddleware()` after `helmet()`.
- `src/config/env.ts` adds `cors.allowedOrigins` field; reads
  `CORS_ALLOWED_ORIGINS` env var with empty default.
- `.env.example` documents `CORS_ALLOWED_ORIGINS`.

### Tests — `src/__tests__/cors.test.ts` (10 cases)
- `parseOrigins` trimming / empty handling.
- `isOriginAllowed` exact + wildcard subdomain.
- Permissive mode: any Origin gets echoed; same-origin (no Origin) passes.
- Strict mode: allowed origin echoes, disallowed origin gets no ACAO header,
  same-origin passes.
- Wildcard subdomain end-to-end via supertest.
- Preflight OPTIONS returns configured methods.
